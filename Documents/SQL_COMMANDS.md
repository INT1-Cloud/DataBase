# SQL Server Command Reference

All examples use **Microsoft SQL Server (T-SQL)** and the `CruiseShipDB` schema. Copy a code block into a new SSMS query window. Run modifying queries only when intended.

## 1. Select database
```sql
USE CruiseShipDB;
```

## 2. List all tables
```sql
SELECT name FROM sys.tables ORDER BY name;
```

## 3. Read rows
```sql
SELECT * FROM Ports;
SELECT PortName, DockingFee FROM Ports;
```

## 4. Filter with WHERE
```sql
SELECT * FROM Voyages WHERE VoyageStatus = 'Scheduled';
SELECT * FROM Cabins WHERE PricePerNight > 2000 AND CabinType = 'Balcony';
SELECT * FROM Ports WHERE Country IN ('Egypt', 'Spain');
SELECT * FROM Passengers WHERE First_name LIKE 'A%';
```

## 5. Sort results
```sql
SELECT * FROM Cabins ORDER BY PricePerNight DESC;
```

## 6. Limit returned results
```sql
SELECT TOP (5) * FROM Cabins ORDER BY PricePerNight DESC;
```

## 7. Insert a row
The ID is generated by `IDENTITY`, so do not specify `PortID`.
```sql
INSERT INTO Ports (PortName, Country, DockingFee)
VALUES ('Valencia', 'Spain', 6100.00);
```
This may fail on a second run due to the `UNIQUE` constraint on `PortName`.

## 8. Update a row
**Caution:** Always check the WHERE condition before executing.
```sql
UPDATE Ports SET DockingFee = 6200.00 WHERE PortName = 'Valencia';
```

## 9. Delete a row
**Caution:** Deletes data. A foreign key may prevent deletion if dependent voyages exist.
```sql
DELETE FROM Ports WHERE PortName = 'Valencia';
```

## 10. JOIN (1:M example)
Each voyage refers to an existing departure port.
```sql
SELECT v.VoyageCode, p.PortName
FROM Voyages AS v
INNER JOIN Ports AS p ON v.DeparturePortID = p.PortID;
```

## 11. JOIN (M:N example)
The junction table `Passenger_Activities` links passengers and activities.
```sql
SELECT p.First_name, p.Last_name, a.ActivityName, pa.TicketsCount
FROM Passenger_Activities AS pa
JOIN Passengers AS p ON p.PassengerID = pa.PassengerID
JOIN Activities AS a ON a.ActivityID = pa.ActivityID;
```

## 12. Aggregate functions and GROUP BY
```sql
SELECT VoyageID, COUNT(*) AS TotalCabins
FROM Cabins
GROUP BY VoyageID;

SELECT AVG(PricePerNight) AS AverageCabinPrice FROM Cabins;
SELECT MIN(PricePerNight) AS CheapestCabin, MAX(PricePerNight) AS MostExpensiveCabin FROM Cabins;
```

## 13. HAVING versus WHERE
`WHERE` filters rows before grouping; `HAVING` filters groups afterward.
```sql
SELECT VoyageID, COUNT(*) AS CabinCount
FROM Cabins
GROUP BY VoyageID
HAVING COUNT(*) >= 2;
```

## 14. Inspect table structure
```sql

```

## 15. Inspect foreign keys
```sql
SELECT fk.name AS FKName,
       OBJECT_NAME(fk.parent_object_id) AS ChildTable,
       OBJECT_NAME(fk.referenced_object_id) AS ParentTable
FROM sys.foreign_keys AS fk;
```

## 16. Constraints in this project
- `PRIMARY KEY`: each table's ID uniquely identifies a row.
- `FOREIGN KEY`: child rows reference valid parent rows.
- `UNIQUE`: rejects duplicate values (for example, passenger email).
- `CHECK`: enforces conditions (for example, salary > 0).
- `DEFAULT`: supplies values for omitted columns (for example, booking date).
- `NOT NULL`: requires a non-NULL value.

Examples from the actual schema:
```sql
CONSTRAINT PK_Ports PRIMARY KEY (PortID)
CONSTRAINT FK_Voyages_Ports FOREIGN KEY (DeparturePortID) REFERENCES Ports(PortID)
CONSTRAINT UQ_Passengers_Email UNIQUE (Email)
CONSTRAINT CK_Crew_Salary CHECK (Salary > 0)
```

## 17. Add a new CHECK constraint (optional improvement)
Only execute if you want to modify the schema:
```sql

ADD CONSTRAINT CK_Voyages_Dates CHECK (ReturnDate > DepartureDate);
```

## Common pitfalls
1. Run the scripts in the right order: parent rows before child rows.
2. Do not rerun `03_insert_sample_data.sql` on an already seeded database.
3. `GO` is an SSMS batch separator, not an SQL statement. The repository avoids it. `CREATE DATABASE` still needs to be run as its own batch.
4. `IDENTITY` values may have gaps; do not assume IDs equal row counts.
5. `WHERE` is critical when updating or deleting.
6. The code is T-SQL; it is not directly compatible with MySQL or SQLite.
